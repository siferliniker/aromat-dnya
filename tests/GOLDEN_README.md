# Golden set этапа 2

Реальный эталон пока не предоставлен. `test_stage2_golden.py` содержит только
синтетические самотесты валидатора. Их зелёный результат не подтверждает точность
LLM и не закрывает гейт этапа.

Для проверки нужны два JSON-файла: разрешённый набор из 30–50 различных текстов
с ручной разметкой и полный результат извлечения для этого же набора. Схема
задаётся моделями `GoldenDataset` и `PredictionSet` в `golden_eval.py`.

Каждый текст должен точно соответствовать принятому `ReviewTextRecord.text`
после удаления внешних пробелов; `input_sha256` — SHA-256 его UTF-8 представления.
Для текста фиксируются источник, ссылка, идентификатор разрешения и основания
получения, передачи LLM, цитирования и хранения. Для каждого ожидаемого аромата
нужны канонический `perfume_id`, `sentiment` и точная цитата из текста. Отрицательные
примеры без упоминаний разрешены, полностью пустой эталон не принимается.

`approval` требует `status: approved`, `label_method: human`, имя проверившего
и дату с часовым поясом. Эти поля являются декларацией: QA отдельно проверяет,
что человек действительно разметил тексты и подтвердил права. Генерация таких
полей моделью не превращает автоматическую разметку в человеческий эталон.

Файл предсказаний содержит тот же `dataset_id`, идентификаторы всех примеров,
их исходные хэши, канонические ID и тональность. Нельзя пропускать неудачные
примеры. Обязательны модель, версия промпта и версия схемы извлечения.

Запуск из корня проекта:

```powershell
.\.venv\Scripts\python.exe tests/golden_eval.py --golden .local/golden/approved-golden.json --predictions .local/golden/predictions.json
```

Программа выводит только идентификатор набора, количества и метрики, без текстов
и цитат. Коды завершения: `0` — оба порога достигнуты, `1` — качество ниже порога,
`2` — некорректные, неполные или неодобренные входные данные.

Метрика названий — micro F1 по каноническим ID: лишние названия снижают precision,
пропущенные снижают recall. Порог — 0,90. Точность тональности делится на число
всех ожидаемых упоминаний: пропуск и неверное название считаются ошибкой.
Порог — 0,85. Дополнительно выводятся precision, recall и доля документов,
для которых полностью совпали названия и тональность. Критерий приёмки
использует оба порога одновременно.
