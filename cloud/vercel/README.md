# Mini App на Vercel

Production: https://aromatia.vercel.app. Проект `aromatia`, команда `gbuo`, тариф Hobby. Локальный компьютер для работы облачной версии не нужен.

`node cloud/vercel/build.mjs` собирает приложение в исключённую из Git папку `.local/vercel/aromatia`. Интерфейс и PNG копируются без изменений из `miniapp/static`; сервер использует существующий `cloud/worker/backend.mjs`. Версия SDK и зависимости зафиксированы в `package-lock.json`.

Личные данные лежат в **private** Vercel Blob, в одном файле `aromatia/state-v1.json`. Состояние и кэш показателей зашифрованы AES-256-GCM до записи, а API проверяет Telegram initData и ID владельца. Публичная оболочка и файлы интерфейса не содержат ключей и отметок. Ключи Telegram, AES и Fragella размещены в Secret-переменных Vercel после отдельного согласия владельца. Файлы `.env*` явно исключены из отправки.

Адаптер `blob-db.mjs` поддерживает только конечный набор запросов действующего backend. Каждая запись читает актуальный файл с `useCache:false` и выполняет условную запись по ETag, с ограниченными повторами конфликта. Для чтения используется `Accept-Encoding: identity`: иначе Brotli возвращает слабый `W/` ETag, непригодный для `If-Match`. Слабый ETag не преобразуется в сильный вручную. Сохраняются сравнение ревизий, защита от повторной реакции и общая блокировка квоты Fragella.

В `.local/vercel/aromatia` уже создана привязка `.vercel/project.json`. Перед размещением проверьте её командой `vercel project inspect --non-interactive --scope gbuo`. Размещение: `vercel deploy --prod --yes --scope gbuo` **из этой папки**. В текущей Windows-установке CLI установлен в `.local/tools/vercel-cli`, а его конфигурация входа — в EFS-папке `.local/AromatiaPrivate/VercelCLI`; для CLI используется параметр `--global-config` с этим путём.

Обновления выполняются через CLI; автоматическое размещение каждого GitHub push пока не настроено. Исходники сохраняются в основном репозитории. Новые развёртывания заменяют приложение, не удаляя private Blob. Не создавайте пустое хранилище вместо существующего: сервер без начального состояния выдаст ошибку, а не сбросит коллекцию. Резервный ключ шифрования хранится в защищённом локальном `.env`.

Прежний адрес Sites не является рабочим входом: пользователь подтвердил там Cloudflare403. Локальная Python-версия сохранена как резерв; ежедневная рассылка остановлена. Локальная и облачная базы после переноса не синхронизируются автоматически.
